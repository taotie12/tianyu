# SZ1 三值排班二维码协议 v1

二维码存放文本，无需网址、账号或服务器。可直接接受 JSON 或带 `SZ1:` 前缀的 JSON：

```text
SZ1:{"v":1,"team":"三值","start":"2026-01-01","days":"TDANOO","tz":"Asia/Shanghai"}
```

此例依次表示 1 月 1 日培训、2 日早班、3 日中班、4 日夜班、5–6 日休息。

| 字段 | 含义 |
| --- | --- |
| v | 必须是数字 1 |
| team | 必须是“三值”，其他值组拒绝导入 |
| start | 有效起始日期 YYYY-MM-DD，2000–2099 年 |
| days | 从起始日期连续每日一个字符，1–400 天 |
| tz | 固定 Asia/Shanghai |

班次编码：`D` 早班，`A` 中班，`N` 夜班，`O` 休息，`T` 培训。大写、不含空格。起始日后的日历日期由软件递增，跨月、跨年和闰年自动处理。结束日也必须在 2099 年内。一次不超过 400 天，较长排班按年拆分。

二维码不提供可信身份认证，不含人员姓名和联系方式，也不携带可执行脚本。只接受此白名单数据结构；数据在用户预览并确认后生效。覆盖仅限导入范围；导入不改变本机班次时间和提前提醒设置。闹钟开启时重新安排闹钟，失败时关闭提醒状态并说明原因，不把失败当作已启用。

上下班时间不从 AI 二维码接收，避免 AI 猜错导致误提醒。使用者必须在软件里确认。夜班日期代表上班开始当天，00:00 是当天零点。

## 可以复制给其他 AI 的提示词

请阅读我上传的 Excel 倒班表，只提取“三值”的实际逐日排班，不要推测固定周期。请生成二维码，二维码中直接存放以下格式的纯文本（不是网址，不是图片下载地址）：

`SZ1:{"v":1,"team":"三值","start":"YYYY-MM-DD","days":"...","tz":"Asia/Shanghai"}`

start 是第一天日期。days 的每个字符对应从 start 开始的连续一天；D=早班，A=中班，N=夜班，O=休息，T=培训。必须按日期排序，跨月跨年正确，不得遗漏或猜测。每个二维码最多 400 天，超过请按年拆分。

若表格是各月日期分列、各值班次分行，请用每个日期所在行的“三值”单元格作为班次，不能把行号当作日号。时间不在二维码里，由使用者在软件内确认。请核对完整日期、总天数和各类班次数量。输出原始 SZ1 文本、起止日期、总天数及清晰二维码，建议纠错级别 M、至少 800 像素、保留白色边距。请使用二维码编码库生成真实可解码的二维码，并回读校验原始文本一致；不要用绘图模型画二维码。无法可靠识别时指出缺失项，不要编造。
